# M0 Parser Capability Matrix

Measured on Windows 11 with Python 3.10.20. Fixtures are synthetic and generated by `tests/fixtures/documents/generate.py`; generated binaries are not committed.

## Decision

- Mandatory M0 core: **PASS**. Deterministic Markdown and `python-pptx` parsing preserve the required text and source locations.
- M1 should use deterministic Markdown/PPTX parsing as the source-aware core.
- MarkItDown 0.1.5 is suitable as an exploratory text-normalization fallback for DOCX, text-layer PDF, and PPTX, but not as the sole provenance parser because the normalized result does not expose paragraph/page/object locations.
- Local image conversion without an explicitly configured multimodal model does not provide OCR and remains unsupported.

## Known limits and follow-up

- Scanned and double-column PDFs, encrypted/corrupt/oversized inputs, chart data, and richer DOCX image provenance remain exploratory challenge rows.
- Every uploaded container must pass the Task 6 security boundary before any parser or MarkItDown call.
- Converted text remains untrusted and cannot enter an Agent system prompt. M5 must normalize it into factual records with source provenance before Fact Store insertion.
- `pip check` reports a pre-existing conflict in the shared `AI` environment: `datasets 5.0.0` requires `fsspec<=2026.4.0`, while the environment has `fsspec 2026.6.0`. Task 8 did not change either unrelated package.

# PPT-maker 系统设计规范

文档层级与交叉引用见 [`docs/README.md`](../../README.md)。本文只定义实现边界与系统不变量；产品目标和功能愿景以仓库根目录 `PPT agent.md` 为上游依据，执行步骤由 `docs/superpowers/plans/` 定义。

状态：已批准
日期：2026-07-22  
目标平台：Windows 11 + Microsoft PowerPoint  
首个纵向场景：项目汇报

开发机固定使用 Conda 虚拟环境 `AI`，当前锁定 Python 3.10.20；开源项目声明支持 Python `>=3.10,<3.13`。Python、Node 和前端依赖必须使用锁文件记录，禁止依赖开发机的全局包状态。

## 1. 产品目标

PPT-maker 是面向中文用户的本地演示文稿 Agent。它通过需求访谈、资料解析、联网研究、大纲审批、样张审批、页面生成、PowerPoint 渲染、质量评测、局部修复和自然语言编辑，输出可编辑的 `.pptx` 文件。

项目同时服务三个目标：

1. 成为可长期使用的个人 PPT 工具；
2. 具备开源所需的可配置性、隐私边界和许可证记录；
3. 展示真实 Agent 工程经验，包括 LangChain、LangGraph、Agent Harness、Human-in-the-Loop、持久化、可观测性、评测、反思和故障恢复。

首版以源码方式启动，只要求前端具有完整演示效果、后端流程正常运行，并能生成真实 PowerPoint。安装包和便携版不属于首版验收范围。

## 2. 已确认的产品边界

### 2.1 支持范围

- 本地运行，不部署云服务器；
- 仅支持 Windows 11 和已安装的 Microsoft PowerPoint；
- 默认生成中文 16:9 演示文稿；
- 支持 Markdown、Word、PDF、PowerPoint、图片、参考 PPT 和普通 PPT 模板；
- 支持原生可编辑文本、形状、图片、表格、常用图表、时间轴、流程图和架构图；
- 支持有限的出现、淡入和擦除动画；
- 支持需求与大纲审批、代表性样张审批；
- 支持自然语言局部修改、页面锁定、撤销和版本回退；
- 支持联网搜索、免费图片和数据素材；
- 支持质量优先和速度优先模式。

### 2.2 非目标

- 多租户 SaaS、账号体系和实时多人协作；
- 复杂动画、宏、插件和复杂 SmartArt；
- 完整复刻任意商业模板；
- 分布式部署、Kubernetes 和跨机器容灾；
- 在没有证据或标签的情况下生成看似真实的数据。

## 3. 总体架构

采用“模块化本地产品 + 独立 Agent Harness + LangGraph 工作流内核 + 双重可观测体系”。

```text
React + TypeScript Web UI
          ↓
FastAPI Application API
          ↓
Project / Conversation Services
          ↓
LangGraph Workflow Runtime
          ↓
Agent Harness
 ├─ Provider 与模型能力路由
 ├─ Prompt / Schema 版本
 ├─ 上下文与预算
 ├─ 工具权限和参数校验
 ├─ 重试、降级、缓存和幂等
 ├─ 隐私与联网策略
 └─ Trace、评测和回放
          ↓
Domain Services
 ├─ Ingestion / Retrieval
 ├─ Research / Assets
 ├─ Outline / Content / Design
 ├─ Slide DSL / PPT Builder
 ├─ Evaluation / Reflection / Repair
 └─ Editing / Versioning
          ↓
SQLite + Local Project Files
```

主应用保持模块化单体。PowerPoint COM 和本地视觉模型使用独立 Worker 进程，原因是 Office 自动化可能卡死，视觉模型需要独立释放显存。两者均通过明确的请求、响应和超时协议与主进程通信。

### 3.1 运行能力分层

| 环境 | 核心Agent与DSL | `.pptx`生成 | PowerPoint渲染/动画 | 本地视觉模型 |
|---|---|---|---|---|
| Win11 + PowerPoint + NVIDIA GPU | 支持 | 支持 | 支持 | 按显存与评测结果启用 |
| Win11 + PowerPoint，无NVIDIA GPU | 支持 | 支持 | 支持 | 降级为几何与规则检查，可选CPU实验 |
| Win11，无PowerPoint | 支持 | 支持 | 不支持；不生成预览与COM动画 | 可用时独立启用 |
| Win11 + WPS | 核心能力可运行 | 可生成标准PPTX | WPS自动化不支持 | 独立于WPS |
| macOS/Linux | 非首版支持范围 | 不作正式保证 | 不支持 | 不作正式保证 |

启动时执行能力探测，并在UI中展示当前可用、降级和不可用功能。PowerPoint缺失不得阻止生成标准 `.pptx`，但必须明确提示没有高保真预览、COM动画和PowerPoint打开验证。

### 3.2 唯一事实源

`ProjectState + DeckBible + SlideDSL` 是系统唯一事实源，`.pptx`、截图和缩略图都是可重新生成的产物。版本、评测、修复和网页内编辑都针对事实源执行。

- 用户在网页内修改时，系统继续维护版本关系和语义信息；
- 导出后在 PowerPoint 中手工修改的内容不自动同步回系统；
- 用户重新上传手工修改后的 PPT 时，将其作为新版本重新解析；
- 重新解析可能丢失组件语义、来源关系和编辑意图，界面必须提前提示。

## 4. 技术职责

### 4.0 技术选型状态

| 能力 | 已确认 | 待 M0/M1 验证，不进入正式生产依赖 |
|---|---|---|
| 运行环境 | Windows 11、Conda `AI`、本机 Python 3.10.20、PowerPoint Office 16 | Python 3.11/3.12兼容矩阵、32/64位Office差异 |
| PPT生成 | `python-pptx`作为候选确定性Builder | 版本锁定、文本测量准确性、模板复用边界 |
| Office渲染 | 独立STA PowerPoint Worker | 受保护视图、文件占用、现有实例兼容性 |
| Agent框架 | LangChain、LangGraph、Pydantic、SQLite Checkpoint | 具体版本锁定和Provider差异 |
| 文档解析 | Markdown与专用PPTX解析路径 | MarkItDown、DOCX/PDF解析器及替代方案 |
| 本地检索 | 已提供BGE-M3、bge-small、MiniLM、Reranker权重 | 默认Embedding、Reranker启用阈值 |
| 视觉检查 | 几何与规则检查必须存在 | 默认VLM、量化方式、CPU降级成本 |
| 联网研究 | Keyed Provider、手动URL、Fact Store边界 | 搜索与图库供应商 |

待验证项只有通过对应门禁并形成 ADR 后，才能成为正式依赖或默认功能。

### 4.1 LangChain

LangChain 用于模型消息、工具、结构化输出、Embedding、Reranker 和 Provider 集成。业务状态、审批和恢复不得隐藏在 Chain 内部。

### 4.2 LangGraph

LangGraph 负责显式状态机、子图、条件路由、审批中断、检查点、恢复和有限修复循环。首版使用 SQLite checkpointer，所有产生外部副作用的节点必须幂等。

主流程：

```text
CREATED
→ INGESTING
→ REQUIREMENT_GATHERING
→ REQUIREMENT_REVIEW
→ RESEARCHING
→ OUTLINE_REVIEW
→ SAMPLE_GENERATING
→ SAMPLE_REVIEW
→ FULL_GENERATING
→ RENDERING
→ EVALUATING
→ REPAIRING
→ USER_REVIEW
→ EDITING
→ COMPLETED
→ RETAINED / PURGED
```

业务状态描述项目处于需求、研究、大纲、生成、评测、编辑或完成的哪个阶段；执行状态描述当前运行控制。执行状态独立包含：

```text
IDLE
RUNNING
WAITING_FOR_USER
PAUSED
CANCELLING
CANCELLED
FAILED_RECOVERABLE
FAILED_FINAL
```

关闭网页不等于取消任务。暂停、取消和失败恢复必须通过持久化执行状态和检查点表达，不能依赖前端连接是否存在。

资料解析、研究、页面生成、评测和编辑分别实现为子图。每个节点声明输入 Schema、输出 Schema、超时、重试上限、失败策略、幂等键和终止条件。

### 4.3 Agent Harness

Harness 是所有 Agent 和工具调用的统一运行入口，包含：

- Provider 能力探测和任务路由；
- Prompt、Schema、模型和工具版本关联；
- 上下文组装、压缩和 Token 预算；
- 工具注册、权限、联网边界和参数校验；
- 超时、退避重试、限流、熔断和降级；
- 幂等、缓存、成本和耗时统计；
- 结构化输出验证与有限修复；
- API Key 脱敏和 Trace 内容过滤；
- 本地事件、运行关联 ID、录制和回放；
- 测试时的 Mock Provider、Mock Tool 和故障注入。

Harness 随纵向切片逐步实现，不能脱离真实需求建设通用框架。

## 5. 模型 Provider

设置页让用户选择 Provider，并填写对应的 API Key、Base URL、模型名和可选参数。不同 Provider 可具有不同配置字段。

支持等级：

1. DeepSeek：首版正式联调、评测和演示；
2. Kimi/Moonshot、通义千问：提供独立预设和适配，获得测试 Key 后标记为正式验证；
3. 其他 OpenAI-compatible 服务：通过通用适配器支持；
4. Claude、OpenAI、Gemini：保留原生适配接口，首版不作为验收阻塞项。

启动或保存配置时探测结构化输出、上下文、视觉输入、工具调用、并发和限流能力。业务节点声明所需能力，路由器不得仅按模型名称猜测。

API Key 与项目数据分离，首版优先使用 Windows Credential Manager；环境变量用于开发和自动测试。密钥不得进入日志、Trace、错误消息或导出文件。

## 6. 资料解析与检索

MarkItDown 作为通用解析入口，格式专用解析器用于补充结构信息：

- DOCX：段落、标题、表格和图片；
- PDF：页面文本、表格、图片和页码；
- PPTX：页面、文本、图片、主题和版式；
- 图片：尺寸、元数据、OCR 和视觉说明；
- Markdown：标题层级、表格和代码块。

所有解析结果转换为统一 `DocumentArtifact`，保留来源文件、页码或对象位置。检索层在 BGE-M3、bge-small 和 MiniLM 中通过专项测试选择默认 Embedding；bge-reranker-base 为可选 Reranker。模型不同时常驻显存。

### 6.1 上传文件安全

所有上传内容均视为不可信输入，并在隔离临时目录中处理：

- 对单文件大小、文件数量、页数、图片像素和解压后总大小设置配置上限；
- 同时检查扩展名、魔数和实际 MIME，拒绝伪造类型；
- 解包前检测压缩比、递归层级、成员数量、ZIP Bomb 和路径穿越；
- 规范化路径并验证最终路径仍位于任务临时目录；
- 禁止执行宏、脚本、OLE 嵌入对象、外部链接对象和可执行附件；
- Office 文件只读解析，含宏文件默认拒绝进入自动化流程；
- 临时目录按任务隔离，正常结束立即清理，异常退出由启动时清理器按所有权标记和过期时间回收；
- 安全拒绝必须产生结构化错误，不得把解析异常原文直接拼入模型 Prompt。

## 7. 联网研究与素材

搜索、抓取、评估和模型总结相互分离：

```text
Research Question
→ Search Provider
→ Page Fetcher
→ Content Extractor
→ Source Evaluator
→ Fact Store
→ LLM Synthesis
```

搜索 Provider 支持独立 API Key，默认选择有免费额度的服务。具体供应商在技术验证阶段根据中国网络可用性、结果质量、许可和免费额度确定。未配置搜索服务时默认关闭联网搜索，用户仍可手动提供网页链接。无需 Key 的非保证搜索仅作为显式开启的实验功能，不进入正式验收链路。

### 7.1 联网安全与内容净化

- 抓取器只允许 `http` 和 `https`，拒绝其他协议、用户信息 URL 和异常重定向；
- DNS 解析前后都检查目标地址，禁止 loopback、链路本地、私网、保留地址、云元数据地址和本机服务；
- 每次重定向重新执行 SSRF 检查，并限制次数、响应大小、耗时和内容类型；
- 下载文件同时检查 MIME、魔数、文件大小、图片像素、许可证元数据和最终来源 URL；
- 网页文字、附件、标题、元数据和图片说明全部视为不可信数据；
- 网页中的“忽略规则”“调用工具”“泄露提示词”等内容不得作为 Agent 指令执行；
- 联网内容不得直接进入 System Prompt 或开发者指令；
- 内容必须经过提取、净化、分段、来源标注、事实候选生成和可信度检查后才能写入 Fact Store；
- Agent 只读取结构化 Fact、Evidence 和 SourceRecord，并保留回到原始证据的引用。

图片采用两种模式：

- 安全模式：只自动使用许可明确、允许再利用的素材；
- 宽松模式：允许普通公开网页图片，使用前提示风险，并记录原链接、作者、访问日期和未知许可状态。

真实事实优先使用可验证来源。允许示例、模拟或估算数据，但必须在页面和来源清单中明确标注，不得与真实数据混淆。所有事实、数据和素材记录到 `source_manifest.json`。

## 8. 内容规划与页面 DSL

LLM 不直接生成 PowerPoint 坐标。生成链路为：

```text
Requirements
→ Outline
→ Page Contract
→ Slide DSL
→ Layout Engine
→ Editable Components
→ PPTX
```

`PageContract` 包含页面目的、核心结论、证据、必含内容、视觉意图、前后页约束和禁止项。`SlideDSL` 包含稳定的 slide ID、版式、元素、来源、锁定状态和设计令牌引用。

### 8.1 DeckBible

每个 Deck 维护全局 `DeckBible`，作为并行页面生成的共享约束：

- 核心叙事、受众、语气和演示目标；
- 术语表、名称规范和数字口径；
- 已验证关键事实及来源；
- 设计令牌、组件规则和素材策略；
- 每页目的、前后依赖和已生成摘要；
- 已使用案例、数据、图片和视觉表达；
- 禁止重复、禁止遗漏和必须保留内容。

所有 Page Writer 在生成前读取固定版本的 DeckBible。页面通过检查后，以受控方式更新摘要索引；并行任务不得无锁直接覆盖全局对象。最终一致性检查负责发现跨页重复、矛盾和术语漂移。

Builder 是确定性组件，不承担自由推理。布局引擎使用约束、设计令牌和组件测量结果计算坐标。生成后的 PPT 通过 PowerPoint COM 进行高保真渲染、缩略图导出和有限动画后处理。

### 8.2 PowerPoint Worker 协议

- COM 初始化和调用必须在 STA 线程中完成；
- 单个 Worker 串行处理 PowerPoint，不在同一 COM 实例上并发；
- 每个任务包含 run ID、幂等键、输入哈希、硬超时、心跳、取消令牌和输出清单；
- Worker 启动独立 PowerPoint 实例并记录其 PID；超时或失去心跳时，只能终止由该 Worker 拥有且 PID 匹配的实例，不能终止用户的其他 PowerPoint；
- 输出先写入同目录临时文件，完成打开验证和产物检查后再执行原子替换；
- 重试前查询幂等记录，已成功任务直接复用，避免重复创建版本；
- Worker 崩溃后主进程将任务标记为 `FAILED_RECOVERABLE`，从最近检查点恢复；
- 自动化开始前检测文件占用、受保护视图和交互弹窗风险；
- 不自动关闭安全警告、不绕过受保护视图；遇到无法安全处理的弹窗时终止任务并提供可操作提示；
- 正常或异常退出均执行 COM 对象释放、临时文件回收和 Worker 所有进程检查。

## 9. 模板和动画

首版模板能力收缩为“简单模板填充”：把用户上传的普通 `.pptx` 作为基础文件，读取其 `slide_master`、`slide_layout` 和标准占位符，选择已有布局并填充文字或图片。首版不承诺从任意商业模板中推断标题区、正文区、图片区，也不重新提取或重建复杂主题。

上传模板时先输出兼容性报告，并提示“只保证标准占位符内容填充，不保证复杂版式复用”。含宏、OLE、ActiveX、外部对象、复杂SmartArt或插件的模板拒绝进入自动化流程。复杂模板识别、颜色分布分析、字体角色推断和视觉版式匹配在M6之后作为独立工作包重新设计。

简单动画通过 PowerPoint Worker 添加；失败时保留无动画的有效 PPT，不阻塞导出。

## 10. 评测、反思与修复

反思不是生成模型的无约束自评，而是有证据、有限次数的评测—修复机制。

### 10.1 四层反思

1. 节点级：Schema、需求覆盖、资料策略、来源和置信度；
2. 阶段级：独立 Evaluator、失败分类、Reflection Plan 和回归检查；
3. 全局级：Deck Critic 检查目标、叙事、重复、矛盾、术语、数据和视觉一致性；
4. 运行后：统计用户修改、失败节点、修复收益和模型/Prompt/工具组合表现。

### 10.2 视觉评测

- 第一层：越界、溢出、遮挡、安全边距、字号、对比度和对齐；
- 第二层：密度、层级、组件数量、图表完整性和跨页一致性；
- 第三层：本地视觉模型判断重心、拥挤、素材相关性和视觉层级。

视觉模型不预先固定。M0 对比 Qwen3-VL-2B、现有 Qwen3-VL-4B、MiniCPM-V-4.6 和 InternVL3.5-2B，按召回率、误报率、JSON合规率、耗时和峰值显存选择。模型未达到阈值时只能给建议，不自动触发修复。

视觉模型采用分级准入：5页只验证加载、预处理和Runner；至少20张PowerPoint真实渲染缺陷页用于功能准入；只有候选接近或需要稳定阈值时才扩展到50页定标。准入要求召回率不低于70%、误报率不高于20%、结构化输出合规率不低于95%，且资源消耗满足本机预算。未达标时视觉检查默认关闭，只以研究预览存在；任何视觉建议在M7之前都不能自动触发修复。

### 10.3 失败时的用户体验

所有可恢复失败必须同时产生结构化错误、用户可理解说明和下一步操作：

| 场景 | 用户界面行为 | 系统行为 |
|---|---|---|
| 搜索无结果 | 提示未找到可靠资料，可修改关键词、切换宽松素材模式或手动提供链接 | 保留原问题和搜索证据，不虚构结果 |
| LLM限流或暂时不可用 | 展示重试状态与基于服务响应的等待信息；允许取消或选择已配置备用Provider | 有上限退避重试，保存检查点 |
| 视觉模型OOM/加载失败 | 明确提示“视觉检查已跳过” | VLM→几何和规则检查→用户提示，不阻塞PPT |
| 单页生成失败 | 缩略图中显示醒目占位页和失败原因 | 继续生成其他页面，将失败页加入修复队列 |
| PowerPoint不可用 | 提示无法提供预览和COM动画 | 仍输出标准PPTX，跳过Office渲染 |
| PowerPoint文件占用或受保护视图 | 提示关闭占用文件或解除受保护状态后重试 | 不自动绕过安全设置，不覆盖原文件 |
| 用户取消 | 展示已安全取消及可恢复位置 | 转入CANCELLED并清理Worker拥有的资源 |

Repair Agent 读取具体失败项并生成最小修复计划。每轮只修改受影响页面或元素，复用未变化页面；超过迭代上限后保留最好版本并向用户说明未解决问题。

## 11. 编辑与版本

自然语言修改先转为 `EditPlan`，包含作用域、操作、保留项、研究需求和风险级别。高影响操作先确认，低风险局部操作可直接执行并允许撤销。

每个版本保存父版本、用户指令、EditPlan、变更页面、评测结果和产物哈希。锁定页面跨版本保留。测试必须证明修改一页不会改变未受影响页和锁定页。

## 12. 存储与隐私

SQLite 保存项目索引、状态、版本关系、Trace 索引和评测记录；大型产物保存在文件系统：

```text
projects/{project_id}/
├─ project.json
├─ uploads/
├─ sources/
├─ artifacts/
├─ renders/
├─ versions/
├─ evaluations/
└─ exports/
```

LangSmith 只用于开发、合成基准和求职演示，不集成到成品。成品始终提供本地结构化 Trace。用户材料默认不发送给 LangSmith，开发 Trace 只使用脱敏或合成数据。

## 13. 前端

前端采用 React + TypeScript，后端采用 FastAPI。前端运行在本机浏览器中，通过本地 API 和事件流通信。

主要工作区：

- 项目首页和历史项目；
- 对话与上传；
- 模型、搜索和资料策略设置；
- 大纲审批；
- 样张审批；
- 生成进度；
- 缩略图和单页预览；
- 自然语言编辑；
- 版本历史；
- 质量与来源报告。

UI 追求简洁、低学习成本和清晰状态反馈。不得展示虚假的精确剩余时间。

## 14. 测试与阶段门禁

每个功能和阶段都必须同时交付测试与评测结果：

1. 单元测试；
2. Schema 和 Provider 合约测试；
3. 集成测试；
4. 固定样例回归；
5. 故障和降级测试；
6. 性能与资源测试；
7. 必要的人工视觉验收；
8. 更新基准结果和测试报告。

未通过门禁的功能不得标记完成。测试类型包括 PPT 结构快照、渲染截图回归、LangGraph 状态恢复、PowerPoint 卡死、API 超时限流、无网络、无视觉模型、编辑影响范围和 Playwright 端到端流程。

测试材料采用三类来源：

1. 自建合成任务和可控缺陷页面，用于准确验证溢出、遮挡、错误来源、状态恢复和局部修复；
2. 许可允许使用的公开 PPT、报告、PDF、Word、图片和数据，用于验证真实材料的复杂性；
3. 用户人工验收，用于判断任务目标、内容可信度、视觉质量和实际修改成本。

公开材料必须记录原始链接、许可证或使用条件、获取日期和本地哈希，不能把来源不明的商业模板提交到仓库。自动评测负责可重复回归，人工验收负责真实可用性和审美，两者都属于阶段完成证据。

评测数据进一步隔离为：

- 开发集：允许查看，用于调试 Prompt、规则和实现；
- 验证集：用于模型选择、阈值校准和停止条件；
- 测试集：最终报告前冻结，开发过程中不得反复查看结果；
- 挑战集：ZIP Bomb、伪造文件、Prompt Injection、事实冲突、低质量图片、Worker 卡死和异常模板等场景。

每个样例具有稳定 ID、版本和数据来源。测试报告必须标明数据划分，禁止把开发集结果当作最终泛化指标。

## 15. 分阶段实施

### 阶段 0：技术验证

验证 PPT 生成与 COM 渲染、动画、文本测量、模板读取、DeepSeek 结构化输出、文档解析、本地视觉模型和搜索/图库候选。每项输出原型、限制和测试报告。

### 阶段 1：最小可运行纵向链路

以文本/Markdown 输入生成第一份可打开的项目汇报 PPT：最小 React/FastAPI 界面、DeepSeek 调用、需求输入、固定大纲、基础 SlideDSL、PPT Builder、PowerPoint 渲染和下载。仅实现支撑真实链路所需的最小 Schema、日志和错误处理。

### 阶段 2：为真实链路补充最小 Harness

加入 Provider Adapter、结构化输出校验、基本重试、运行 ID、本地 Trace、密钥存储、项目存储和 SQLite checkpoint；将阶段 1 的直接调用迁移到 Harness，并用回归测试证明结果未退化。

### 阶段 3：完整项目汇报纵向切片

加入需求访谈、大纲审批、6–10 页项目汇报、DeckBible、基础组件、预览、几何检查、暂停恢复和人工验收。随后才按真实故障逐步加入缓存、回放、熔断和故障注入。

### 阶段 4：资料解析与检索

加入 Word、PDF、PPT、图片解析，本地检索、Reranker、来源定位和长文档处理。

### 阶段 5：联网研究与素材

加入搜索、网页提取、免费图库、数据来源、版权模式、事实冲突和来源清单。

### 阶段 6：设计系统、样张和模板

加入设计令牌、版式选择、样张审批、标准母版/布局占位符填充、高级组件和简单动画。复杂主题提取与商业模板识别不包含在本阶段。

### 阶段 7：评测和自动修复

加入完整规则、事实检查、视觉模型、Deck Critic、Reflection Plan、Repair Agent 和质量报告。

### 阶段 8：自然语言编辑与版本

加入 EditPlan、页面锁定、增量重建、撤销、回退和版本比较。

### 阶段 9：任务模式扩展

依次增加工作汇报、学术答辩、数据报告、商业路演、教学课件、活动宣讲和自定义模式。每种模式拥有独立槽位、叙事策略和基准任务。

### 阶段 10：完整评测与开源包装

建立 20+ 基准任务、消融实验、人工盲评、多 Provider 对比、性能成本报告、LangSmith 演示 Trace、README、架构图、演示视频、许可证清单和开源准备。

## 17. 成功标准

首版目标阈值如下，M0 可基于测量结果调整阈值，但所有调整必须写入 ADR，不能在看到最终测试集结果后反向修改：

- 在 DeepSeek API 下完成项目汇报端到端流程；
- 需求槽位覆盖率不低于 90%；
- 无效追问率不高于 10%；
- PowerPoint 文件成功打开率 100%；
- 关键元素可编辑率 100%；
- 严重越界、溢出和遮挡率 0%；
- 公共事实可追溯率不低于 95%；
- 局部编辑影响范围准确率不低于 95%；
- Repair 后目标缺陷数量相对修复前减少至少 50%，且不得新增严重缺陷；
- 首稿人工可用率不低于 80%，质量优先模式成熟后目标不低于 90%；
- 人工可用定义为：任务目标、内容可信、结构完整、视觉可读四项均达标，且无需重做超过 20% 页面；
- 分别报告质量模式和速度模式的 P50/P95 总耗时、首响应时间和单页耗时；
- 报告峰值显存、峰值内存、API Token、估算费用和本地模型加载时间；
- 报告完成任务所需人工修改轮数、自动修复轮数和失败恢复率；
- 审批、暂停、取消、重启和检查点恢复均通过集成测试；
- 每个阶段有测试报告和可复现实验；
- 最终简历中的指标均由冻结测试集、Trace 和人工盲评支持。

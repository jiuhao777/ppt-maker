# PPT-maker 产品质量恢复与 Deck Blueprint 设计

> 状态：用户已批准  
> 日期：2026-07-27  
> 作用：修正当前 M2/M3 实现与既有设计的缺陷，并定义后续实现的唯一产品流程。  
> 优先级：本规范与旧的 M2、M3 规格冲突时，以本规范为准。

## 1. 背景与目标

PPT-maker 的目标不是把文字搬进 PowerPoint，而是把模糊需求转化为目标导向、事实可信、视觉统一且可编辑的演示文稿。

当前实现已有项目管理、模型配置、需求访谈、大纲、联网事实、返工和基础 PPTX 生成，但仍存在以下系统性问题：

- 大纲缺少全局叙事与逐页施工约束；
- 概略大纲、完整文案和版式规划混在一次模型调用中；
- M2 中文页型与 M3 英文枚举不兼容；
- 章节页、表格页存在确定性运行错误；
- JSON 被按字符截断，可能形成残缺上下文；
- 局部返工仍会被范围外缺陷阻塞；
- 页数和时长检查因字段类型变化而失效；
- 联网图片、许可、来源和真实素材尚未形成闭环；
- PPT 只生成图片占位框，来源引用未写入成品；
- M3 评测只覆盖单一案例和文本布局，门禁存在假阳性；
- 生成产物依赖 Streamlit 会话，刷新后不可恢复；
- 部分异常路径可能展示模型原始返回内容。

本轮建立以下完整闭环：

```text
需求访谈
→ 概略大纲
→ 用户批准
→ 联网研究
→ 详细 Deck Blueprint 与候选素材
→ 用户批准
→ SlideDSL 编译
→ PPTX 生成与 PowerPoint 渲染
→ 质量检查与限定范围修复
→ 用户审阅、返工和交付
```

## 2. 产品原则

1. `Project State + Deck Blueprint` 是唯一事实源，`.pptx` 是生成产物。
2. 用户明确选择高于 Agent 自动路由。
3. 事实、数据和图片必须可追溯；不确定内容必须显式标记。
4. 视觉化不等于每页配图。Agent 根据页面任务选择图表、结构图、照片、插画、图标卡片或纯排版。
5. 模型负责语义理解和规划，确定性代码负责验证、状态、坐标与文件生成。
6. 修改必须先计算影响范围，未受影响内容不得被模型隐式改写。
7. 每个阶段具有可恢复检查点、明确失败状态和机器可读评测证据。
8. API Key 只存在于当前会话内存，不写入 SQLite、文件、日志、Trace 或导出包。

## 3. 正式产品流程

### 3.1 输入与需求访谈

输入包括主题描述、Markdown、DOCX、PDF、PPTX、图片、参考 PPT 和简单模板。

需求访谈确认演示场景、目标受众、核心目标、演示时长、目标页数、交付环境、内容重点、禁止内容、视觉风格、联网策略和资料边界。

每轮最多询问一个高影响问题，并显示追问理由和已确认信息摘要。阻塞问题提供“不知道/由系统提出待验证假设”选项。

### 3.2 概略大纲

概略大纲用于确认方向并节省 Token，只包含：

- 全局目标、受众和叙事框架摘要；
- 3–4 个主要章节；
- 页面顺序、页型和页面目的；
- 每页结论草案；
- 前后页逻辑关系；
- 需要联网补充的研究缺口。

概略大纲不生成完整正文、演讲备注、坐标、图片或详细视觉说明。

### 3.3 批准门 A

用户可以增加、删除、合并、拆分、重排或返工概略大纲。只有用户批准后才能执行联网研究和详细 Blueprint 生成。

### 3.4 联网研究

研究阶段根据已批准的页面目标生成 ResearchTask，收集事实、数据、案例和候选图片。联网内容必须经过安全抓取、净化和事实化后进入 Fact Store 或 Asset Store。

### 3.5 详细 Deck Blueprint

详细 Blueprint 是 PPT 的施工规范。它按“全局 → 章节 → 页面批次”生成，避免一次返回超大 JSON。所有 Writer 读取同一个 Deck Bible。

### 3.6 批准门 B

用户审阅逐页文案、布局、视觉类型、演讲备注、事实、来源及候选图片。用户可以保留、更换、重新搜索、上传图片或改为无图版式。批准后锁定 Blueprint 和素材版本，才允许生成 PPT。

### 3.7 PPT 生成与修复

系统将 Blueprint 编译为 SlideDSL，生成可编辑 PPTX，使用 PowerPoint 渲染，并执行内容、几何、文件和视觉质量检查。修复只能作用于缺陷页面及明确依赖页面。

## 4. Deck Blueprint

所有核心模型包含 `schema_version`，首版值为 `1`。

### 4.1 全局锚点 `DeckBible`

包含：

- 演示场景、受众、核心目标、时长、页数和交付环境；
- 叙事框架、核心论点和行动号召；
- 语气、术语表、关键事实和禁止内容；
- 主色、辅助色、中性色及使用规则；
- 标题、正文、备注的字体和字号层级；
- 图片、插画和图标风格；
- Logo、页码、页脚和引用格式；
- 页面摘要、已使用案例和图片，防止跨页重复；
- 内容密度、动画等级和全局质量红线。

### 4.2 章节 `BlueprintSection`

每章包含章节 ID、标题、顺序、目标、观众问题、核心结论、包含页面、前后关系、密度节奏和记忆锚点。

### 4.3 页面 `BlueprintPage`

每页包含：

- 页面 ID、顺序和规范化页型；
- 页面目的和结论式标题；
- 一级结论；
- 最多三个二级支撑论点；
- 三级补充说明和来源；
- 正文、关键数字和演讲者备注；
- 内容边界和禁止项；
- 上一页承接语与下一页引导语；
- 视觉类型；
- 布局模板、区域比例、对齐、留白和元素位置；
- 图表类型及字段映射；
- 最多两个重点高亮元素；
- `fact_ids`、`asset_ids` 和来源清单；
- 内容密度与预计讲述时间。

### 4.4 规范化枚举

模型自由文本不得直接进入编译器。页面类型至少包括：

```text
cover, contents, section, conclusion, text, image_text, cards,
comparison, timeline, process, architecture, data_chart, case,
quote, interaction, qa, ending
```

布局与视觉类型同样使用枚举，并在模型输出后执行中英文别名归一化。未知值在语义层返回可恢复校验错误，不进入 PPT 编译。

### 4.5 页面内容红线

- 标题必须表达结论，而非仅写“市场分析”等范畴词；
- 二级论点不超过三个；
- 默认正文不超过 100 个汉字；
- 禁止超过三行的大段正文；
- 需要口头解释的细节进入演讲者备注；
- 页面重点不超过两个；
- 数据图表必须有标题、口径和来源；
- 无关、低清、有水印或许可不明且未警示的图片不得使用。

## 5. Agent 架构

LangGraph 负责编排以下节点：

| 节点 | 职责 |
|---|---|
| Requirement Extractor | 抽取需求字段与置信度 |
| Interview Planner | 选择一个最关键的缺口问题 |
| Outline Architect | 生成概略大纲 |
| Research Planner | 把大纲缺口拆成研究任务 |
| Research Executor | 执行搜索并写入 Fact Store |
| Blueprint Writer | 分章节、分页面生成详细 Blueprint |
| Consistency Reviewer | 检查叙事、术语、事实与视觉一致性 |
| Asset Curator | 搜索、校验并推荐候选素材 |
| Slide Compiler | 确定性地将 Blueprint 编译为 SlideDSL |
| Quality Inspector | 执行内容、几何、渲染和视觉检查 |
| Repair Planner | 生成最小影响范围的修复计划 |

每个节点使用版本化 Pydantic 输入输出，在 SQLite 保存业务状态和执行检查点，具有超时、重试上限、失败类型和恢复策略，不直接操作其他节点的数据表，也不直接修改 PPTX。

## 6. 联网研究与素材

### 6.1 联网路由

- `ALWAYS`：必须联网；无博查 Key 时禁止启动研究并引导配置。
- `AUTO`：规则筛选后由模型判断时效性和资料缺口。
- `NEVER`：不联网，仅使用用户材料并提示时效风险。

用户选择优先于自动判断。

### 6.2 事实链路

```text
搜索结果
→ URL 与 SSRF 校验
→ 安全抓取
→ 正文提取
→ Prompt Injection 净化
→ 原子事实提取
→ 来源与时间校验
→ Fact Store
```

Fact Store 至少保存陈述、来源标题、URL、作者或机构、发布日期、抓取时间、置信度和排除状态。公共关键结论优先要求两个独立来源。

### 6.3 图片链路

首版使用 Provider 适配层，优先接入可追溯的开放素材源，并支持用户上传或提供链接。Asset Store 至少保存：

- 本地隔离路径和内容哈希；
- 原始 URL 和页面 URL；
- 作者、来源平台和许可；
- MIME、字节大小、像素尺寸；
- 审批状态和使用页面；
- 宽松素材风险标记。

下载必须检查：

- 仅允许 HTTP/HTTPS；
- DNS 解析后的全部地址；
- 本机、内网、云元数据、IPv4 映射 IPv6；
- 每次重定向后的目标；
- 用户名、密码和异常端口；
- 超时、响应大小、MIME 和像素尺寸；
- 文件真实类型与扩展名；
- 许可和水印风险。

### 6.4 素材失败降级

找不到合格图片时按顺序改写关键词、提示用户上传、改为图表或结构图、使用完整无图版式。导出的成品不得包含灰色图片占位框。

## 7. 返工与版本

### 7.1 版本状态

概略大纲和 Blueprint 版本使用：

```text
DRAFT → APPROVED → SUPERSEDED
```

批准版本被编辑时创建新草稿；旧版本保留且可以比较和恢复。保存新版本后界面自动切换到新版本。

### 7.2 影响分析

用户返工指令先转换为 `EditPlan`，展示需求字段变化、受影响章节和页面、需要重新研究的事实、需要重新选择的素材及将失效的下游版本。

核心目标、受众、叙事线或章节变化触发关联页面重写。单页措辞、布局或图片变化只处理相关页面。

### 7.3 范围保护

- 未受影响页面使用结构哈希验证完全不变；
- 局部质量检查只阻止本轮新增或影响范围内的缺陷；
- 全局检查可以报告历史问题，但不得阻止合法局部修复；
- 自动修复最多一次；
- 修复后缺陷未减少时，不替换上一有效版本。

## 8. PPT 编译与 PowerPoint Worker

### 8.1 分层

```text
Deck Blueprint（语义事实源）
→ SlideDSL（确定性布局指令）
→ PPTX（生成产物）
→ PowerPoint PNG（验收渲染）
```

### 8.2 首版组件

支持封面、目录、章节、结论页、图文、卡片、对比、时间线、流程、架构、数据图表、案例、金句、Q&A 和结尾。

文字、形状、表格、图表、页脚来源和演讲者备注保持可编辑。复杂动画、宏、SmartArt 和嵌入对象不在本轮范围。

### 8.3 排版规则

- 画布默认 16:9；
- 封面标题默认不小于 44pt，普通页标题默认不小于 32pt，正文默认不小于 18pt；
- 优先缩短内容，不能依靠无限缩小字号解决溢出；
- 标题默认单行；
- 保持安全边距、对齐、留白和对比度；
- 连续三页高密度页后必须插入轻页或调整节奏；
- 图片使用裁切适配，禁止拉伸变形；
- 来源脚注、页码和固定元素遵循 Deck Bible。

### 8.4 Worker 不变量

- COM 在 STA 线程运行；
- 单 Worker 串行操作 PowerPoint；
- 任务有心跳、硬超时和取消；
- 只终止 Worker 自己创建的 PowerPoint PID；
- 输出先写任务临时目录，验证后原子发布；
- 幂等键阻止重复产物；
- 崩溃后从检查点恢复；
- 首版要求干净 PowerPoint 环境，并明确处理文件占用和受保护视图。

## 9. Streamlit 产品界面

首版分为设置、项目输入、需求访谈、概略大纲、研究中心、详细 Blueprint、PPT 生成与预览、返工与版本历史、质量报告与导出。

API Key 存在 `st.session_state`，刷新后丢失是预期安全行为。项目、任务、批准版本、事实、素材、SlideDSL、PPTX 和缩略图必须持久化，刷新后可恢复。

Provider 异常只展示认证失败、限流、超时或服务不可用等安全类别，不展示 URL、请求体、响应体、模型原文或 Key 片段。

## 10. 失败状态

业务状态与执行状态分开记录。执行状态至少包括：

```text
RUNNING, WAITING_FOR_USER, PAUSED, CANCELLING, CANCELLED,
FAILED_RECOVERABLE, FAILED_FINAL, COMPLETED
```

失败页面保留草稿和具体缺陷。搜索、图片、渲染和视觉模型失败均有明确降级路径，不得无提示吞掉错误。

## 11. 质量与测试

### 11.1 测试分层

- 单元测试：Schema、归一化、路由、安全、布局和版本；
- 契约测试：Provider、Fact Store、Asset Store、Blueprint 和 SlideDSL；
- 集成测试：访谈、大纲、研究、返工、PPT 生成；
- Streamlit AppTest：真实 widget 状态和刷新恢复；
- Office 测试：打开、渲染、超时、取消、弹窗和孤儿进程；
- 在线测试：DeepSeek、博查和图片源；
- 人工验收：叙事、视觉、图片相关性和首稿可用性。

### 11.2 必须覆盖的回归

- 章节页与表格页可编译；
- 中文页型能归一化；
- JSON 在结构边界裁剪，不产生半截 JSON；
- 页数和时长规则生效；
- 局部返工不被范围外缺陷阻塞；
- 未影响页面哈希保持不变；
- 被排除事实不会进入后续流程；
- 日志、异常和 UI 不泄露秘密或模型原文；
- 无合格图片时不导出占位框；
- 刷新后生成产物和任务可恢复；
- 每一种正式页型和布局至少有一个编译案例。

### 11.3 量化门槛

| 指标 | 门槛 |
|---|---:|
| 文件成功打开率 | 100% |
| 严重越界、遮挡率 | 0% |
| 公共事实可追溯率 | ≥95% |
| 局部返工影响范围准确率 | ≥95% |
| 需求覆盖率 | ≥90% |
| 标题结论化率 | ≥90% |
| 严重文字溢出率 | 0% |
| 正文密度违规率 | ≤5% |
| 图片相关性人工评分 | ≥4/5 |
| Repair 后缺陷 | 必须减少 |

评测集分为开发集、验证集、测试集和挑战集。测试集不得用于反复调 Prompt。

## 12. 实施工作包

### P0：可靠性止血

修复确定性崩溃、类型契约、结构化上下文裁剪、局部返工范围、失效质量规则、异常泄露和虚假门禁。

### P1：两阶段大纲与 Blueprint

实现概略大纲、Deck Bible、详细 Blueprint、两个批准门、版本与影响分析。

### P2：联网事实与真实素材

完善博查研究，新增图片 Provider、Asset Store、安全下载、许可与素材审批。

### P3：专业 PPT 生成

扩展 SlideDSL、正式布局、图表、真实图片、来源、备注、持久化产物和 PowerPoint 渲染闭环。

### P4：产品体验与综合验收

完善 Streamlit 工作台、失败恢复、综合评测、Office 验收、门禁证据和文档。

每个工作包均执行：

```text
失败测试 → 最小实现 → 模块测试 → 全量回归
→ 机器可读评测 → 人工检查点 → 独立提交
```

## 13. 非目标

- 复杂动画；
- 宏、SmartArt 和嵌入对象；
- WPS COM；
- macOS/Linux PowerPoint 自动化；
- 云部署和多租户 SaaS；
- 商业模板的完整语义反向解析；
- 未经评测达标的视觉模型自动修改 PPT。

# M2 全局返工、版本体验与动态访谈改进设计

## 1. 背景与目标

M2 首次人工验收发现：

- 用户修改行业、主题或关键节点时，相关页面不会联动更新；
- 新版本保存后界面仍停留在旧版本，历史版本入口不清晰；
- 访谈固定检查六类字段，两次使用产生完全相同的六个问题；
- 两次大纲均生成七项研究任务，缺少合并和必要性检查。

本改进在 M2 范围内增加可控 AI 返工、明确版本导航、简短动态访谈和研究任务去重。联网执行、详细页纲和 PPT 制作仍不属于 M2。

## 2. AI 返工

### 2.1 两种模式

大纲区增加“AI 返工”面板：

- **全局返工**：重新检查需求摘要、叙事主线、全部页面和研究任务；
- **局部返工**：用户选择起始页面，Agent 只修改选中页和确认的关联页。

用户使用自然语言输入修改意见，例如“将制造业改为服务业，并同步修改案例、痛点和措辞”。

### 2.2 两阶段执行

第一阶段生成 `ReworkImpact`：

- 返工模式；
- 用户反馈；
- 直接影响页面；
- 关联影响页面；
- 每页受影响理由；
- 是否需要更新 RequirementBrief；
- 是否需要重新计算研究任务。

界面先展示影响范围。用户确认后才执行返工。

第二阶段生成新大纲：

- 全局返工允许重新生成全部页面；
- 局部返工只能修改已确认影响范围内的页面；
- 未受影响页面必须保持页面 ID 和内容；
- 修改页面尽量保持页面 ID，只有新增页面生成新 ID；
- 结果通过 Schema 和反思检查后才写入数据库。

任一步失败都不产生新版本，界面继续显示原版本。

## 3. 版本行为

每个大纲版本增加创建方式和返工摘要：

- `GENERATED`
- `MANUAL_EDIT`
- `AI_GLOBAL_REWORK`
- `AI_LOCAL_REWORK`
- `RESTORED`

新版本保存成功后：

- 自动切换到新版本；
- 版本选择器显示 `v编号 · 状态 · 创建方式`；
- 所有历史版本始终可选择并只读查看；
- 显示父版本、返工摘要和结构化差异；
- 恢复历史版本会复制为新的 `DRAFT`，不改变历史记录。

UI 通过“待选版本”会话值在下一次 rerun 前设置选择器状态，避免修改已实例化 Streamlit widget。

## 4. 动态访谈

### 4.1 核心字段

通用核心字段仍为目标、场景、页数、受众、重点和风格，但不再默认全部询问。只有会明显改变大纲、且无法从材料可靠确定的字段才阻塞。

### 4.2 任务专属字段

系统先识别任务类型，再从受控模板中选择最多两个必要字段：

- 工作或项目汇报：成果指标、主要风险、决策诉求；
- 商业路演：商业模式、融资目标、竞争优势；
- 学术答辩：研究问题、研究方法、实验结论；
- 教学课件：学习目标、学员基础、课堂时长；
- 数据报告：指标口径、时间范围、比较基准；
- 活动宣讲：行动号召、活动规则、参与对象。

模型不能自由增加字段，只能选择受控字段并生成贴合上下文的措辞、理由和选项。

### 4.3 问题体验

- 通常询问 3–6 个问题，硬上限 8 个；
- 每个问题只表达一个意思；
- 优先提供 2–4 个简短选项，同时允许自由输入；
- 始终提供“不知道/不确定”；
- 次要缺口直接形成可见的待验证假设；
- 显示“预计还需约 N 个关键问题”；
- 相同字段或相同语义不得重复询问。

## 5. 研究任务

研究任务不设置固定数量。新大纲批准或完成 AI 返工后重新计算：

- 以标准化问题语义、素材类型和目标页面为去重依据；
- 同一搜索可以共同解决的相邻任务合并；
- 删除只用于润色、不能支撑事实或视觉内容的任务；
- 保留每个页面不可缺少的事实、数据、案例、图片和引用缺口；
- 全局返工后不得残留已被替换主题或行业的任务。

研究任务仍在大纲批准后正式写入；返工预览只显示预计任务变化。

## 6. 错误与安全

- 影响分析和返工结果各允许一次结构修复；
- Provider 失败沿用固定安全错误，不显示原始响应；
- API Key 仅为调用参数，不进入返工请求、版本、检查点或日志；
- 返工写入使用单个 SQLite 事务；
- 返工失败、取消或中断不改变当前大纲与研究任务；
- 批准后的版本发生返工时，新版本为 `DRAFT`，必须再次批准。

## 7. 验收标准

自动化和人工验收必须覆盖：

- 将“制造业”改为“服务业”后，所有受影响页面和研究任务不残留制造业内容；
- 局部返工不修改影响范围外页面；
- 用户确认影响范围前不调用最终返工；
- 失败返工不产生版本；
- 手工保存、恢复和 AI 返工后自动选中新版本；
- 所有历史版本可查看，差异、父版本和创建方式准确；
- 相同研究任务被去重，不采用固定任务数量；
- 不同任务类型产生不同的必要专属问题；
- 已知字段不重复询问；
- 问题总数不超过 8，通常为 3–6；
- 问题简短、单一，并提供选项和“不确定”路径；
- 现有 M2 与 M1 自动测试全部通过；
- 用户重新执行真实 DeepSeek/UI 流程并确认体验。

## 8. 非目标

本改进不实现联网搜索执行、详细页纲、完整文案、PPTX 生成、视觉模型或 M3 功能。

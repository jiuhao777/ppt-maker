# Blueprint 图片槽位与精确布局设计

## 1. 目标

把详细大纲升级为真正可执行的 PPT 施工图。每页不仅描述“写什么”，还必须明确内容层级、元素位置、视觉关系、图片计划、演讲备注和前后衔接，使 PPT 生成器无需再次猜测页面结构。

本次同时修复两个现有问题：

1. 每页只能选择一张图片，后选图片会替换前一张。
2. 图片被选中但当前页型没有图片区域时，M3 编译失败并无法生成 PPTX。

## 2. 范围

本轮包含：

- 每页 0–4 个独立图片槽位；
- 人类可读的页面施工说明；
- 机器可执行的标准化布局数据；
- 分槽搜索、选择、替换和降级；
- 旧版单图片 Blueprint 的兼容迁移；
- 封面、章节、引用、结束页等特殊页型的图片布局；
- Blueprint 编辑、审批、编译及 PPTX 生成闭环；
- 1–4 图片页面和关键失败场景的自动测试。

本轮不包含：

- 网页内自由拖拽式 PPT 编辑器；
- 任意形状设计或像素级图形绘制；
- 复杂 PowerPoint 动画；
- 从 PowerPoint 手工修改结果反向同步 Blueprint。

## 3. 方案选择

### 3.1 采用的方案

采用“双层表达”：

- 可读层：用户编辑布局说明、内容层级、图片用途和关键视觉选项；
- 执行层：系统生成标准化元素与几何数据，M3 直接据此编译。

普通界面只展示易理解的字段。精确坐标放在高级设置中，用户可查看和调整，但无需手工填写才能继续。

### 3.2 未采用的方案

- 仅保存自然语言：实现简单，但 M3 仍需猜测，输出不稳定。
- 只保存精确坐标：机器执行稳定，但用户编辑负担过高，模型输出也更容易产生无效几何数据。
- 直接开发拖拽画布：超出当前阶段目标，会显著增加前端和状态同步复杂度。

## 4. 页面施工图

每个 `BlueprintPage` 必须表达：

- 页码、页型、页面目的和一句话结论；
- 一级、二级、三级内容；
- 页面布局说明和对齐规则；
- 标题、正文、图表、图片、来源、页脚等元素的区域；
- 0–4 个图片槽位；
- 图表类型、数据、位置和高亮规则；
- 重点元素与视觉层级；
- 禁止出现的内容；
- 演讲者备注；
- 与上一页、下一页的逻辑衔接；
- 页面密度、记忆锚点和预计讲解时长。

可读施工说明由结构化字段确定性渲染，不另存一份可能失真的自由文本副本。

## 5. 数据模型

### 5.1 标准化区域

新增 `LayoutRegion`：

- `x`、`y`、`width`、`height` 使用 0–1 的画布比例；
- 坐标以页面左上角为原点；
- 所有字段必须在 0–1 范围内；
- `x + width <= 1`，`y + height <= 1`；
- M3 编译时转换为 13.333 × 7.5 英寸画布坐标。

比例坐标可以跨模板和分辨率复用，比直接保存像素或英寸更稳定。

### 5.2 布局元素

新增 `LayoutElementPlan`：

- `element_id`：页面内唯一标识；
- `kind`：`title`、`subtitle`、`body`、`chart`、`image`、`source`、`footer`、`page_number`；
- `region`：标准化区域；
- `z_index`：绘制层级；
- `alignment`：左、中、右；
- `font_size`：文本元素字号；
- `color_token`：引用 Deck Bible 的颜色角色；
- `content_ref`：引用页面字段或图片槽位；
- `fit`：图片使用 `cover` 或 `contain`。

系统只允许受支持的元素类型和样式令牌，避免模型生成不可执行的自由格式。

### 5.3 图片槽位

新增 `AssetSlot`，每页最多 4 个：

- `slot_id`：页面内唯一且稳定；
- `role`：`background`、`hero`、`logo`、`photo`、`screenshot`、`illustration`、`icon`、`case`、`decorative`；
- `subject`：要寻找的具体内容，例如“DeepSeek 官方标志”；
- `search_query`：实际搜索词；
- `purpose`：图片对页面结论的支撑作用；
- `required`：是否必须有图片；
- `region`：图片位置和尺寸；
- `fit`：`cover` 或 `contain`；
- `z_index`：绘制层级；
- `fallback`：`no_image`、`icon`、`text`、`simplified_layout`；
- `selected_asset_id`：当前选中的素材，可为空。

槽位顺序即界面和施工说明中的图片顺序。一个槽位只能批准一张图片，不同槽位互不影响。

### 5.4 Schema 版本

`DeckBlueprint.schema_version` 升级为 2。读取版本 1 时执行确定性迁移：

- 没有图片字段时生成空槽位列表；
- 原 `asset_search_query` 转为一个 `hero` 槽位；
- 原 `asset_ids` 的第一项成为该槽位的 `selected_asset_id`；
- 原页型和 `visual.kind` 用于生成默认布局元素；
- 保存新版本时只写 schema 2。

迁移不能修改历史数据库记录；迁移结果在内存中使用，用户保存或返工时创建新的 Blueprint 版本。

## 6. 布局生成

### 6.1 自动布局

模型负责输出语义内容和布局意图，系统使用受控布局生成器产生合法区域。生成器根据以下信息选择布局：

- 页型；
- 内容块数量；
- 图片槽位数量；
- 是否存在图表；
- 页面密度；
- 图片角色和宽高比。

布局生成器必须提供 0、1、2、3、4 图的确定性模板，并保证：

- 所有元素在安全边距内；
- 图片和正文没有严重重叠；
- 标题区不被图片覆盖；
- 页脚、来源和页码位置稳定；
- 关键元素至少保留最小可读区域；
- 轻重页节奏不因图片数量而失控。

### 6.2 特殊页型

封面、章节、引用和结束页必须支持图片布局：

- 封面：背景图或右侧主视觉；
- 章节：背景图、侧边图或无图大标题；
- 引用：背景图或人物/案例图；
- 结束页：背景图、品牌图或无图行动号召。

选择图片后，页面必须切换到能够表示全部已选槽位的布局。不得批准一个编译器无法渲染的素材状态。

### 6.3 高级调整

高级设置允许调整：

- 元素区域；
- 图片裁切方式；
- 层级；
- 文本对齐；
- 受控字号和颜色令牌。

保存前统一校验区域边界、元素引用、槽位数量和页面内唯一 ID。非法值不得写入新版本。

## 7. 图片工作流

图片搜索按槽位执行：

1. Blueprint 明确每个槽位需要什么图片以及为什么需要；
2. 用户点击某个槽位的搜索；
3. 搜索服务使用该槽位的 `search_query`；
4. 候选素材保存 `page_id` 和 `slot_id`；
5. 用户为该槽位选择一张图片；
6. 只替换同一槽位之前批准的图片；
7. 其他槽位的选择保持不变；
8. Blueprint 同步更新该槽位的 `selected_asset_id`。

页面可以同时使用至多四张已选图片。素材仍必须通过现有 SSRF、MIME、文件大小、像素数量和解码安全检查。

## 8. 缺图与错误处理

### 8.1 必选槽位

必选槽位没有有效本地素材时，Blueprint 不得批准。用户必须：

- 选择一张可用图片；或
- 把该槽位明确切换为一种降级方案。

### 8.2 可选槽位

可选槽位没有图片时自动应用 `fallback` 并重新计算布局，不阻塞 PPTX 生成。

### 8.3 素材失效

已选图片文件不存在、下载失败或未通过安全校验时：

- 必选槽位返回可操作的安全错误；
- 可选槽位执行降级；
- 不向用户展示内部路径、响应正文或异常堆栈；
- 不允许出现“已批准但无法被布局表示”的状态。

## 9. Blueprint 编辑与版本

- 修改施工图、布局、图片槽位或选图后创建新 Blueprint 版本；
- 修改已批准版本会撤销批准，新版本状态为 `DRAFT`；
- 保存后界面自动切换到新版本；
- 旧版本仍可查看和对比；
- 版本对比至少显示页数、页标题、页型、元素、图片槽位和选图变化；
- 恢复旧版本通过复制创建新版本，不覆盖历史。

## 10. M3 编译契约

M3 不再根据页型猜测图片应放在哪里，而是消费 `LayoutElementPlan`：

- 每个选中图片槽位必须恰好对应一个 `image` 元素；
- `content_ref` 必须引用真实槽位；
- 图片记录必须属于同一项目、Blueprint 版本、页面和槽位；
- 图表元素必须引用有效结构化图表数据；
- 编译器把标准化区域转换成 SlideDSL 坐标；
- 编译后继续运行几何和质量检查；
- 输出失败不得留下半成品文件。

旧版 Blueprint 在迁移后走同一编译路径，不维护第二套长期编译逻辑。

## 11. 用户界面

每页编辑区按以下顺序展示：

1. 页面目标和核心结论；
2. 内容层级；
3. 布局与视觉说明；
4. 图片槽位卡片；
5. 图表和重点高亮；
6. 演讲备注与逻辑衔接；
7. 高级布局设置。

每张图片槽位卡片显示：

- 图片用途和目标内容；
- 搜索词；
- 页面位置摘要；
- 当前已选图片；
- 搜索、替换、清除和使用降级方案操作。

普通用户不需要理解坐标。界面用“右侧 60%”“底部三列”等摘要表达，坐标只在高级设置中展示。

## 12. 质量规则

Blueprint 审批前检查：

- 每页图片槽位不超过 4 个；
- 页面、元素和槽位 ID 唯一；
- 所有区域合法；
- 每个图片元素引用一个真实槽位；
- 每个选中槽位被一个图片元素表示；
- 必选槽位已选图或已明确降级；
- 标题、正文、图片、图表、来源和页脚没有严重越界或遮挡；
- 单页正文、要点数量和视觉重点符合现有质量规则；
- 图表类型与数据关系匹配；
- 所有公共事实保持可追溯。

## 13. 测试与验收

自动测试必须覆盖：

- Schema 2 的字段边界、唯一性和最多四槽限制；
- Schema 1 到 Schema 2 的迁移；
- 同页不同槽位分别批准图片；
- 替换一张图片不影响其他槽位；
- 1、2、3、4 图布局；
- 无图和缺图降级；
- 封面、章节、引用、结束页选图后可编译；
- 图片元素与槽位一一对应；
- 非法区域、失效图片和错误槽位归属被拒绝；
- 修改后创建并自动选择新版本；
- Blueprint 编译为 SlideDSL；
- PPTX 成功生成、可由 PowerPoint 打开和渲染；
- 严重溢出、越界和遮挡为 0。

人工验收至少使用：

- 一页多品牌 Logo；
- 一页生活场景图与产品截图组合；
- 一页三图案例对比；
- 一页四图矩阵；
- 带背景图片的封面或结束页；
- 删除其中一张可选图片后重新生成。

成功标准：

- 每页可独立选择并保留最多四张图片；
- 详细大纲完整呈现文案、位置、样式和衔接；
- 所有选中图片均出现在正确页面和区域；
- 特殊页型选图不再导致编译失败；
- 旧项目可继续打开并生成；
- PPTX 成功生成且不存在严重遮挡、越界和残留占位符。

## 14. 实施边界

按最小闭环分阶段实施：

1. Schema 2、迁移和校验；
2. 分槽素材存储与选择；
3. 自动布局与施工说明；
4. Blueprint 编辑界面；
5. M3 编译和特殊页型；
6. 回归测试与真实 PowerPoint 验收。

每阶段先写失败测试，再做最小实现，并在阶段结束运行相关测试。不得借此重构无关模块。

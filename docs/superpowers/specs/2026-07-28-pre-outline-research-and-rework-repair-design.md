# 前置研究与返工质量修复设计

## 目标

修复两项阻塞问题：

1. 大纲返工因可确定修复的结构缺陷而失败；
2. 时效性主题在生成概略大纲之后才联网，导致大纲建立在过时知识上。

## 联网时序

需求抽取与时效性路由完成后、概略大纲生成前执行基础研究。

- `AUTO` 判断需要联网且有博查 Key：立即搜索，净化结果并写入 Fact Store；概略大纲读取这些事实。
- `AUTO` 判断需要联网但无 Key：进入用户确认状态。UI 显示时效风险，提供“仍然继续”和“返回配置 Key”；未经确认不生成大纲。
- `ALWAYS` 无 Key：继续保持阻塞，要求配置 Key。
- `NEVER`：不联网，允许生成，并显示用户已选择忽略时效风险。
- 搜索失败：不得静默使用旧模型知识冒充最新信息；显示失败原因类别，由用户明确选择重试或继续生成非时效性大纲。

概略大纲批准后的页面级研究继续保留，用于补充大纲产生的具体数据、案例、图片和证据缺口。前置研究负责“方向正确”，后置研究负责“页面证据完整”。

用户的“继续生成非时效性大纲”授权只对当前研究决策有效，持久化为不含秘密值的状态；新的需求分析或时效性决策会清除该授权。

## 返工确定性修复

模型首次返工后，先执行不创造新事实的规范化：

- 页面顺序按当前列表重新编号；
- `target_slides` 同步为实际页面数；
- 每页关键点最多保留前三条；
- 包含数字但没有材料位置、已验证来源或缺口说明的页面，增加“该数字需要来源核验”的 Research Gap。

规范化后执行范围校验和质量检查。局部返工的范围外页面必须逐字保持不变，因此规范化只能修改受影响页面；全局元数据只在全局返工时同步。若仍有无法确定修复的缺陷，保留现有的一次模型修正；第二次仍失败才拒绝保存。

## 数据流

```text
需求抽取 → 时效性路由
  → 无需联网 / 用户授权降级
  → 或前置搜索 → Fact Store
→ 生成概略大纲（读取 active facts）
→ 用户批准
→ 页面级补充研究
→ 详细 Blueprint
```

## 验收

- “中国最先进的大模型”等时效主题在有 Key 时，搜索先于 `generate_outline`，事实进入大纲 Prompt。
- `AUTO` 无 Key 时不会直接生成；用户确认后才继续，且 UI 明示内容可能过时。
- 新的需求分析会撤销旧的降级授权。
- 返工结果出现页数不一致、顺序错误、四个以上关键点或无来源数字时可确定修复并成功保存。
- 无来源数字只能转为待核验缺口，不能伪造来源。
- 局部返工范围外页面序列化结果保持不变。
- API Key、搜索原文和 Provider 异常详情不进入 SQLite、日志或 UI。

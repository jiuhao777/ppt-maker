# 中国网络优先图片发现设计

## 目标

解决详细大纲生成后普遍没有可用图片的问题。首版面向中国个人用户，在不依赖代理网络的条件下，优先找到与页面内容相关、可正常下载和嵌入 PPTX 的图片。

## 原因

当前流程只有 Openverse 和 Wikimedia。候选还会受到许可证、作者、归因字段及下载验证的多轮过滤；最终 UI 将搜索失败、许可过滤、网络失败和图片验证失败统一显示为“不可用”，无法判断真实原因。

## 来源优先级

1. **博查网页图片发现**：使用现有会话级博查 Key 搜索中文网页，对结果页面执行安全抓取，提取 `og:image`、`twitter:image` 和正文主图。
2. **国内图片搜索适配器**：搜狗图片、360 图片和百度图片作为无 Key 降级来源。适配器彼此隔离，任一接口结构变化或限流不会中断其他来源。
3. **开放图库补充**：Openverse 和 Wikimedia 仅在当前网络可访问时补充结果，不作为正式链路的唯一依赖。
4. **无图降级**：所有来源均失败时，将页面标记为无图版式建议，不导出占位框。

Pexels、Pixabay 和 Unsplash 暂不进入首版正式链路：它们需要额外 Key 或对 API 热链、下载回调和归因有额外要求，并且不能保证中国网络稳定访问。

## 查询策略

每个图片页从 `asset_search_query` 生成最多三组确定性中文查询：

- 原始主题；
- 原始主题 + 页面视觉类型（摄影、插画、科技背景、产品图）；
- 原始主题 + “横版 高清 16:9”。

查询只用于图片检索，不调用额外模型，不包含用户上传材料原文、联系人、账号、密钥或内部编号。

## 候选与下载

- 不按许可证状态、作者或归因字段过滤；
- 作者、来源页面和原始图片 URL 可为空作者，但来源 URL 必须保留在本地记录，用于缓存、去重和故障排查；
- UI 和 PPTX 不显示作者、许可证或来源；
- 候选按来源优先级、分辨率、横版比例和重复哈希排序；
- 每页最多保留五个已验证候选。

以下安全检查不可关闭：

- 仅允许 HTTP/HTTPS；
- 禁止本机、内网、云元数据地址、异常端口和 URL 凭据；
- 每次重定向重新验证 DNS 与目标地址；
- 校验 MIME、真实图片格式、文件大小、像素尺寸和解码结果；
- 限制页面 HTML 与图片下载大小、超时和重定向次数；
- 不执行脚本、宏、SVG、HTML 中的指令或网页文本；
- 网页只做结构化图片 URL 提取，不进入 Agent Prompt。

## 错误与 UI

每页展示统计：

- 搜索返回候选数；
- 许可过滤数（新模式应为 0）；
- 页面抓取失败数；
- 下载失败数；
- 格式或尺寸拒绝数；
- 最终可用数。

用户只看到简短中文原因，不显示内部 URL、异常正文或密钥。重新搜索只影响当前页。

## 配置

- 新旧项目统一使用个人宽松图片策略，不再要求用户确认许可风险；
- 博查 Key 继续复用现有会话输入，不写入 SQLite；
- 国内无 Key 适配器默认启用；
- 各来源具有独立超时和失败熔断，单个来源故障不会拖慢整个项目。

## 验收

- 在不使用代理网络且未配置国外图库 Key 时，中文主题能从至少一个国内来源获得候选；
- 配置博查 Key 后，博查网页结果的主图可进入候选；
- 缺少作者和许可证的图片仍能通过候选模型与下载流程；
- 图片与页面查询相关、横版优先且不拉伸；
- 搜索结果页或图片指向内网、伪造 MIME、超限文件、SVG 或损坏图片时必须拒绝；
- 任一来源超时后其他来源继续运行；
- 所有来源失败时自动使用无图版式，不影响 PPTX 生成；
- API Key、网页正文和内部异常不会进入数据库、日志、UI 或 PPTX。

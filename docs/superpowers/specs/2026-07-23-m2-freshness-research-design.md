# M2 时效性路由与轻量联网核验设计

## 1. 目标与边界

M2 在访谈和结构大纲生成前识别任务是否依赖近期事实。对于“中国大模型现状”等高时效主题，系统使用博查搜索核验当前代表对象、发布日期、能力和市场信息，避免直接采用模型的过时记忆。

本功能只补充形成可靠大纲所需的少量公共事实。大纲批准后的完整数据、案例、图片和引用研究仍属于后续联网研究阶段。

## 2. 联网策略

项目提供三态策略：

| 策略 | 行为 |
| --- | --- |
| `AUTO` | 默认值。由时效性路由决定是否联网 |
| `ALWAYS` | 用户强制联网；没有搜索 Key 时阻塞并提示配置 |
| `NEVER` | 用户禁止联网；只使用材料和模型知识，并提示时效风险 |

用户选择始终覆盖智能路由。策略是非敏感项目设置，可以持久化。

## 3. 时效性路由

`FreshnessRouter` 接收用户主题、已提取需求和材料摘要，返回结构化决策：

- `requires_web`；
- `reason`；
- `freshness_level`：`LOW`、`MEDIUM` 或 `HIGH`；
- `verification_topics`：最多五项需要核验的公共事实类别；
- `safe_queries`：最多五条脱敏查询。

以下内容默认具有较高时效性：

- “现状、最新、近期、趋势、排名、市场”等时间指示；
- 在售产品、模型、公司、人物、价格、政策、法规和行业数据；
- 竞品、代表案例、发布日期和能力比较。

纯创意、固定历史时期、只总结用户材料或内部资料的任务默认不联网。路由先使用确定性规则识别明显情形，仅在规则无法判断时调用已配置的模型输出结构化决策。路由不得依赖搜索结果反向决定是否搜索。

## 4. Provider 与秘密值

API 设置区增加“博查 API Key（可选）”。模型 Key 和博查 Key 都只保存在当前 Streamlit 会话内：

- 不写入 SQLite、项目 JSON、Checkpoint、日志或 Trace；
- 页面刷新或进程退出后清除；
- 日志脱敏过滤器同时覆盖两种 Key；
- 第三方 HTTP 日志保持 `WARNING`；
- Provider 异常经安全错误映射后再展示。

搜索层使用统一 `SearchProvider` 契约，首个适配器为博查。未来替换 Provider 不改变 M2 状态和事实模型。

## 5. 执行流程

1. 用户输入主题、材料和联网策略。
2. M2 提取初始需求。
3. `AUTO` 执行时效性路由；`ALWAYS` 和 `NEVER` 直接采用用户选择。
4. 需要联网且已配置博查 Key 时，执行有限查询。
5. 搜索结果经过 URL 安全检查、提取、净化和事实化。
6. 合格事实写入项目级 `FactStore`，保存来源、发布日期和访问时间。
7. 需求访谈和大纲生成只读取事实记录，不读取原始网页，也不把网页内容放入 System Prompt。
8. 界面展示联网原因、查询状态、事实来源和排除来源操作。
9. 用户排除来源后，使用剩余事实重新生成大纲。

## 6. 无 Key 与失败处理

`AUTO` 判断需要联网但未填写博查 Key 时：

- 不阻塞流程；
- 明确提示主题具有时效性但未完成联网核验；
- 继续离线生成，并把相关内容标为“待验证”。

`ALWAYS` 未填写 Key 时阻塞生成，用户必须填写 Key 或更改策略。

认证失败、限流、超时、无结果或内容不合格时，不得虚构最新事实。系统保留查询状态并允许离线继续；已经通过验证的事实仍可使用。

## 7. 联网安全

- 只允许 HTTP/HTTPS；
- DNS 解析和每次重定向均检查目标地址；
- 阻止本机、内网、云元数据、IPv4 映射 IPv6 和异常端口；
- 限制重定向次数、响应大小、下载时长和正文长度；
- 网页内容始终视为不可信数据；
- 删除脚本、样式、隐藏文本和指令式内容；
- Prompt Injection 文本不得改变 Agent 指令、工具权限或联网策略；
- 事实记录必须保留 URL、站点、标题、发布时间（如可得）、访问时间和支持片段；
- 未通过安全或来源检查的内容不得进入 `FactStore`。

## 8. 数据契约

新增核心契约：

- `WebPolicy`：`AUTO | ALWAYS | NEVER`；
- `FreshnessDecision`：路由结果；
- `SearchQuery` 与 `SearchResult`：Provider 中立的搜索数据；
- `FactRecord`：经过净化和事实化的证据；
- `ResearchRun`：记录策略、决策、查询、状态和安全错误类型。

所有持久化契约包含 `schema_version`。任何契约都不得包含 API Key、Authorization Header 或原始请求对象。

## 9. 界面

API 设置区：

- 模型 Provider 与模型 API Key；
- 博查 API Key（可选）；
- 两者分别进行连接测试，不互相阻塞。

项目区：

- 联网策略三选一，默认“自动判断”；
- 显示“已自动联网”或“未联网”的理由；
- 显示来源标题、站点、日期和 URL；
- 支持排除来源并重新生成；
- 未核验内容使用清晰的“待验证”标记。

## 10. 测试与验收

自动测试至少覆盖：

- “中国大模型现状”在 `AUTO` 下触发联网；
- “总结上传的季度汇报”在 `AUTO` 下不联网；
- `ALWAYS` 和 `NEVER` 覆盖路由结果；
- `AUTO` 无 Key 可降级，`ALWAYS` 无 Key阻塞；
- 博查成功、认证失败、限流、超时和无结果；
- URL、DNS、重定向、响应限制和 Prompt Injection 防护；
- 事实来源、发布日期和访问时间完整；
- 网页原文不进入 System Prompt；
- 两种 Key 均不落盘且日志无泄漏；
- 排除来源后重新生成只使用剩余事实；
- 搜索失败时不产生无来源的“最新事实”。

人工验收使用至少两个中文案例：

1. “中国大模型现状”：结果应包含近期有代表性的模型，且关键判断有来源和日期。
2. “总结我上传的季度汇报”：默认不联网，且不会把内部材料发送给搜索服务。

M2 轻量联网核验通过后，才能把真实 DeepSeek 访谈与大纲体验标记为正式完成。

## 11. 非目标

- 图片、视频和商业素材搜索；
- 大规模深度研究；
- 自动采信单一来源；
- 绕过付费墙、登录或 robots 限制；
- 在没有搜索服务时抓取搜索结果页作为正式降级；
- 将用户私密材料原文发送给搜索 Provider。

# M2 需求访谈与结构大纲设计

## 1. 目标

M2 建立首个可运行的 Agent 业务闭环：读取用户描述和材料，提取已知需求，仅追问影响大纲的关键信息，生成可编辑的结构大纲，并在用户明确批准后产出研究任务清单。

M2 的完成边界是：

- 结构大纲已由用户批准；
- 未解决的事实、数据、案例和图片需求已转为结构化研究任务；
- 状态可持久化、恢复和回放。

联网研究、详细页纲、完整文案和 PPT 制作不属于 M2。后续顺序为：

`结构大纲批准 → 联网研究与事实整理 → 详细页纲 → 用户批准 → PPT 制作`

## 2. 输入边界

M2 支持：

- 自然语言任务描述；
- Markdown；
- DOCX；
- 文本型 PDF；
- PPTX。

材料经 M0 安全检查后解析。只保存净化后的文本、来源定位和摘要；原始文件放入任务隔离临时目录，解析结束或异常退出后清理。

图片和扫描型 PDF 暂不做视觉识别。系统必须明确提示“暂未识别”，不得推测其内容。单个文件解析失败不阻塞其他材料。

## 3. 技术方案

采用受控 LangGraph 状态图和严格结构化模型输出，不使用自由自治 Agent。

流程为：

`材料解析 → 需求抽取 → 缺失项判断 → 动态追问 → 结构大纲生成 → 用户修改 → 用户批准 → 研究任务生成`

约束如下：

- 已从材料或对话确定的信息不得重复询问；
- 每轮最多提出一个高价值问题；
- 只有会实质改变大纲的信息才阻塞流程；
- 次要缺口以明确假设记录；
- 用户批准前不得进入联网阶段；
- 每个模型节点必须通过 Schema 校验；
- 首次校验失败只允许一次模型修复请求；
- 再次失败进入 `FAILED_RECOVERABLE`，不得丢失已有状态。

## 4. 组件边界

### 4.1 Material Ingestor

调用既有安全检查和解析能力，将文件转换为统一的材料片段。每个片段保留文件名、页码或对象定位、文本和解析警告。

网页内容不在 M2 接入。

### 4.2 Requirement Extractor

从任务描述、材料和既有对话中提取 `RequirementBrief`。它只归纳有证据的信息，不负责追问。

### 4.3 Interview Planner

比较当前需求与大纲最低输入条件，决定：

- 提出一个问题；
- 记录一个非阻塞假设；
- 或结束访谈并生成大纲。

每个候选缺口记录字段置信度，并按以下顺序评分：是否阻塞大纲、对叙事和页面分配的影响、当前置信度、用户回答成本。默认业务优先级为“演示场景、受众、核心重点、风格偏好”，但实际评分可以根据材料上下文调整，避免僵化问卷。

每个问题同时提供简短追问理由。用户可选择“不知道/不确定”，并明确授权系统生成一条待验证假设，避免流程被阻塞。

### 4.4 Outline Generator

生成叙事主线、章节和页面级结构。M2 页面内容包括标题、页面目标、核心要点和页面类型，不生成最终文案。

### 4.5 Outline Editor

支持修改页数、页面顺序、标题、目标、要点和章节归属；支持新增、删除页面。每次保存形成新版本，旧版本只读且可恢复。

编辑器提供相邻版本的结构化差异，至少显示页数、页面增删、顺序和标题变化。大纲版本状态为：

- `DRAFT`：当前可编辑草稿；
- `APPROVED`：用户明确批准的不可变版本；
- `SUPERSEDED`：已被更新版本取代的历史版本。

新草稿批准后，原 `APPROVED` 版本转为 `SUPERSEDED`。恢复历史版本会复制出新的 `DRAFT`，不修改历史记录。

### 4.6 Reflection Checker

在大纲展示前执行一次受控检查：

- 目标和重点是否被覆盖；
- 页数与演示时长是否匹配；
- 叙事是否完整；
- 页面是否重复；
- 未知内容是否被误写为事实；
- 每个资料缺口是否形成研究任务；
- 是否重复询问已知信息。

反思只能修正当前结果，不能增加未经用户要求的目标，也不能绕过批准门禁。

## 5. 数据模型

### 5.1 RequirementBrief

包含 `schema_version`，以及：

- 用途和任务类型；
- 受众；
- 使用场景；
- 演示时长和目标页数；
- 语言和语气；
- 视觉风格偏好；
- 核心重点；
- 可用材料；
- 数据与来源边界；
- 质量或速度偏好；
- 用户已确认信息；
- 系统明确假设；
- 尚缺信息。

字段允许未知，但阻塞字段必须在生成大纲前解决或由用户接受假设。

### 5.2 ConversationTurn

记录角色、显示内容、时间、对应需求字段和轮次。不得保存 API Key、请求头或 Provider 原始响应。

### 5.3 DeckOutline

包含 `schema_version`、项目 ID、版本、状态、父版本 ID、叙事主线、目标页数、章节和页面列表。每页包含：

- 稳定页面 ID；
- 顺序；
- 章节；
- 标题；
- 页面目标；
- 核心要点；
- 页面类型；
- 已知来源定位；
- 资料缺口。

批准动作锁定具体版本，而不是可变的“最新版本”。

### 5.4 ResearchTask

包含 `schema_version`，以及：

- 待回答问题；
- 目标页面 ID；
- 素材类型：事实、数据、案例、图片或引用；
- 重要级别；
- 建议检索方向；
- 完成状态。

研究任务只描述需要查找什么，不在 M2 执行搜索。

## 6. 状态与持久化

业务状态至少包括：

- `COLLECTING_REQUIREMENTS`
- `WAITING_FOR_USER`
- `GENERATING_OUTLINE`
- `OUTLINE_REVIEW`
- `OUTLINE_APPROVED`
- `FAILED_RECOVERABLE`
- `FAILED_FINAL`

执行状态沿用 M1 的运行、暂停、取消和租约语义。业务状态和执行状态分开保存。

RequirementBrief、对话、材料片段、大纲版本、批准记录和研究任务写入 SQLite。LangGraph 使用持久化检查点。刷新或进程重启后恢复最近检查点；执行中断任务恢复为可恢复失败，不伪装为空闲状态。

API Key 仍只存在 Streamlit 当前会话内，不写入数据库、检查点、导出 JSON、日志或 LangSmith。

`WAITING_FOR_USER` 不持有 Worker、模型连接或执行租约，可长期保存。首版是无后台服务的本地应用，因此不发送定时通知，也不因等待超过 24 小时而标记失败；用户重新打开项目时显示“继续访谈”入口和最后活动时间。

## 7. 用户界面

项目工作区增加三个连续区域：

1. **任务与材料**：填写主题和目标，上传支持文件，显示解析结果与警告。
2. **Agent 访谈**：每次展示一个问题、追问理由和“不知道/不确定”选项；固定显示已确认信息摘要和当前访谈进度，用户可直接修正已确认字段。
3. **大纲编辑器**：编辑、增删和排序页面，查看版本差异，恢复旧版本并明确批准。

批准按钮必须说明批准的版本及后续动作。批准后如用户再次编辑，应形成新版本并撤销原批准状态。

未配置 API Key 时保留全部项目数据，提示输入 Key 后继续。任务运行时提示用户不要刷新，但刷新后仍应安全恢复。

## 8. 错误处理

- 文件解析失败：显示具体文件和安全错误类别，不显示内部堆栈；
- Provider 超时、认证、限流或格式错误：统一转换为安全错误，可重试；
- 大纲生成或修改失败：保留上一成功版本；
- Streamlit 刷新或进程中断：从检查点恢复；
- API Key 缺失：暂停需要模型的动作，不清除状态；
- 日志：继续使用 M1 全局脱敏，第三方 HTTP/SDK 日志保持 `WARNING` 或更高。

## 9. 测试与验收

实现采用测试先行。自动化测试覆盖：

- RequirementBrief、DeckOutline 和 ResearchTask Schema；
- 已知字段不会再次被 Interview Planner 提问；
- 每轮至多一个问题；
- 问题包含追问理由，“不知道”可生成明确的待验证假设；
- 缺口评分和默认优先级行为；
- 非阻塞缺口转为假设；
- 大纲增删改、排序、版本保存和恢复；
- 版本差异及 `DRAFT`、`APPROVED`、`SUPERSEDED` 转换；
- 批准锁定具体版本；
- 批准后编辑会撤销批准；
- 未批准无法进入后续阶段；
- 材料部分失败不影响成功材料；
- 模型结构错误的一次修复和最终可恢复失败；
- 刷新、SIGTERM 中断和检查点恢复；
- API Key、材料正文和 Provider 原始异常不进入日志。
- 核心契约包含可校验的 `schema_version`。

场景集至少包含：单主题、材料充分、材料不足和多文件输入。M2 门槛为：

- 需求关键字段覆盖率不低于 90%；
- 无效追问率不高于 10%；
- 每个未解决事实缺口都有研究任务；
- 页面顺序和版本恢复准确率 100%；
- 未批准越过门禁次数为 0；
- 自动化测试全通过；
- 人工确认至少一条完整 Streamlit 流程可用。

体验目标为从材料上传到结构大纲批准的平均访谈轮次不超过 15 轮。人工修改页面比例作为观察指标记录；在形成稳定评测基线后再判断是否采用“不超过 30%”的质量门槛，M2 首版不以减少用户主动编辑为代价优化该指标。

模型质量评测使用开发集调试，验证集确定 Prompt 和阈值，最终测试集不参与反复调优。

## 10. 非目标

M2 不实现：

- 联网搜索、网页抓取和 Fact Store；
- 图片或扫描 PDF 识别；
- 详细页纲和完整页面文案；
- SlideDSL、PPTX 生成、渲染和动画；
- 复杂模板识别；
- 多 Agent 自由协作。
